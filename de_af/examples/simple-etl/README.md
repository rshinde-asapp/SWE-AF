# Simple ETL Pipeline Example

This example demonstrates DE-AF's output for a simple CSV → Parquet pipeline with data quality validation.

## Pipeline Overview

**Goal**: Transform raw user data from CSV to analytics-ready dimension table.

**Data Flow**:
1. **Extract**: Read `data/users.csv` (raw user records)
2. **Transform**: Staging (stg_users.sql) → clean, deduplicate, type cast
3. **Load**: Dimension table (dim_users.sql) → SCD Type 1 (overwrite)
4. **Quality**: Great Expectations suite + dbt tests validate output

## Components

### 1. SQL Transformations (`sql/`)
- `staging/stg_users.sql`: Clean raw CSV (trim whitespace, cast types, filter invalid rows)
- `marts/dim_users.sql`: Create dimension table with business keys

### 2. dbt Project (`dbt_project/`)
- dbt models mirror SQL transformations
- `schema.yml`: Data quality tests (unique user_id, not_null email, accepted_values status)
- Custom test: `assert_no_null_user_ids.sql`

### 3. Airflow DAG (`airflow/dags/simple_etl_dag.py`)
- Schedule: Daily at 2 AM UTC
- Tasks: extract_csv → dbt_run_staging → dbt_run_marts → dbt_test → validate_great_expectations
- Retries: 2, timeout: 1 hour

### 4. Infrastructure (`terraform/`)
- Mock Snowflake warehouse definition
- S3 bucket for staging data
- IAM roles for Airflow

### 5. Data Quality (`great_expectations/`)
- Expectation suite for users table:
  - Column user_id: unique, not null
  - Column email: regex validation, not null
  - Column created_at: date range validation

### 6. Integration Test (`tests/test_pipeline.py`)
- Fixture: 10 sample user records
- Test: Run full pipeline, assert output has 10 rows, no nulls in user_id

## Running the Example

```bash
# Install dependencies
pip install dbt-core dbt-snowflake great-expectations apache-airflow

# Run dbt models
cd dbt_project
dbt run
dbt test

# Validate with Great Expectations
great_expectations checkpoint run users_checkpoint

# Run integration test
pytest tests/test_pipeline.py -v
```
